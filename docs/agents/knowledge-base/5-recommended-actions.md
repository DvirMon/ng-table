# Recommended actions

Eight actions, each argued from something this repo **already does**, not from a generic best
practice. Ordered by dependency: A1–A2 unlock A3–A5; A6–A8 are independent.

## The one structural insight

`status.md` is the best thing in this knowledge base and nobody has generalised it. It is
generated from the specs' own frontmatter by `tools/generate-status.ts`, carries a DO-NOT-EDIT
banner, and **therefore cannot drift**. `README.md` sits beside it, hand-maintained, and had a
bullet pointing at `2-columns/work/` — a folder that never existed.

Same repo, same week, two navigation files: the generated one was correct, the hand-written one
was not. Every action below is a variation on *move the agent-facing surface to the generated side
of that line*.

---

## A1 — Generate `docs/llms.txt`, don't hand-write it

`llms.txt` ([llmstxt.org](https://llmstxt.org/)) is a small markdown file at a root or subpath
giving an LLM a curated map instead of making it crawl. Format, exactly:

```markdown
# Project name

> One-blockquote summary carrying the key information.

Optional body prose.

## Section

- [Link title](url): optional link details

## Optional

- [Secondary stuff](url): agents may skip this section
```

Rules that matter for us: the H1 is the only required part; `## Optional` is a reserved convention
meaning "skippable under context pressure"; a file covers the URLs under its path and **the most
specific one wins**, so per-context files are legal and correct. `llms-full.txt` is the sibling
convention holding the full expanded content in one file.

Proposal: `libs/table/docs/llms.txt`, generated by a new `tools/generate-llms-txt.mts`,
wired as `npm run table:llms`, with a `--check` mode.

Why generated, not written:

- Precedent exists twice over — `table:status` and `table:overloads` / `table:overloads:check`.
  A third generator is a known pattern here, not a new one.
- The inputs are already in frontmatter: `title`, `type`, `capability`, `spec`, `code`,
  `audience`. Section grouping comes from the layer folders (`0-product` … `3-ui`, `adr`), which
  are already the right taxonomy.
- `## Optional` maps cleanly onto work efforts and task plans — real content, but not what an
  agent should load first.
- A hand-written `llms.txt` becomes `README.md`: correct the day it ships, wrong within a month,
  and wrong in the one file every agent reads first.

Division of labour afterwards: `README.md` stays the human entry point (prose, entry-points-by-
role); `llms.txt` becomes the agent entry point; `status.md` stays the maturity view. Three
surfaces, one owner each, instead of one hand-maintained file trying to be all three.

## A2 — Make `status:` a controlled vocabulary

Blocks A1, A3, A4, and `qmd --filter`. 74 files carry `status:`, with values ranging from
`complete` to a 180-character sentence. `capability:`/`spec:`/`code:` are the counter-example —
controlled, and therefore `status.md` generates from them.

Proposed enum, reusing the D1–D3 field vocabulary already decided in
`state-feature-competitive-audit/decisions.md`: `stub | drafted | drilled | accepted | shipped |
superseded | archived`. Prose that doesn't fit moves to a new free-text `note:` key, where nothing
tries to parse it.

## A3 — Add `last-reviewed:` and `owner:`

`date:` records when a doc was *written*. Nothing records when it was last checked against
reality — so 22 files dating to 2026-07 are indistinguishable from 22 verified yesterday. The one
intervention that held across the documentation surveys was a named owner plus a last-reviewed
date; cadence alone did not.

## A4 — `--check` gates in CI

`table:overloads:check` already establishes the pattern: a generator that asserts its own output
is current and fails the build when it isn't. Three checks belong behind it:

1. **Link check** — the 31 breaks just fixed were found by a throwaway script, not by anything
   that runs. Two of the three root causes were mechanical (self-prefixed paths, wrong `../`
   depth) and fully scriptable.
2. **`llms.txt` drift** — `generate-llms-txt.mts --check`.
3. **Frontmatter schema** — `status:` within the enum, `last-reviewed:` present above work-effort
   level.

## A5 — Add the query layer (`qmd`), one collection per context

Detail in [2-qmd-retrieval.md](2-qmd-retrieval.md). Sequenced after A2 because metadata filtering
— the part that makes it better than grep rather than merely different — needs the controlled
vocabulary. Gate on the ten-question trial before committing.

`llms.txt` and `qmd` are not alternatives: `llms.txt` is the map read on entry (cheap, always
loaded, no index to go stale), `qmd` is the search run mid-task (needs an index, needs
re-indexing). Ship A1 first — smaller, no runtime dependency, and it helps even if the `qmd` trial
fails.

## A6 — Close the fan-out gap in the work-effort pipeline

The sharpest mismatch between our flow and the LLM Wiki method. Their **ingest** operation updates
*the 10–15 pages a source touches* and logs it. Our pipeline (`1-ticket → 2-decisions → 3-spec →
4-issues → 5-tasks`) writes one work folder; propagation into the standing docs is manual and
undocumented.

That gap is what produced the drift: ADR-0015 reopened ADR-0007, and both architecture files kept
stating the old shape. Fix: a **propagation step** at effort close-out — list every standing page
the effort's decisions touch, update them in the same PR, record the list in `state.json` beside
`githubIssues`. Machine-checkable later; useful immediately.

## A7 — Archive landed work efforts

29 efforts, many landed, all in the default read path. The LLM Wiki rule is archive-aware:
archived material stays on disk and drops out of default queries. With A2 in place this is one
`status: archived` per effort, honoured by `llms.txt` (dropped, or demoted to `## Optional`) and
by the `qmd` collection config. Directly reduces what an agent loads before it starts.

## A8 — An Error Book per context

Append-only page recording the knowledge base's own mistakes — "both architecture files wrote
docs-root-relative paths", "column-rules.ts moved and three docs kept the old path" — read by the
next compile. From arXiv 2605.25480; the one mechanism in the method with no analogue here.
`~/.claude/rules/` captures *process* corrections; nothing captures *knowledge-base* corrections.

Cheapest version: `docs/error-book.md`, one dated bullet per incident, appended during grooming.
No tooling.

## What not to do

- **Don't restructure `docs/`.** The four numbered layers keyed to the implementation stack are a
  better axis for a code repo than a generic topic wiki. Nothing in the research argues otherwise.
- **Don't hand-write `llms.txt`.** See A1.
- **Don't let a grooming agent edit in place.** Detection and drafting automate; approval does
  not. PR, atomic commit per concern, human merges.
- **Don't adopt `[[wikilinks]]` yet.** Cheap and useful for orphan detection, but a repo-wide
  convention change competing with A1–A4 for the same attention. After A4.
