A group header does not have to be a row of cells. Here it is one banner spanning the whole table — no column separation — carrying its label, a centred count, and its own Add row to group button. The engine only emits kind: 'group' plus groupKey and aggregates; the markup is entirely this host's.

Every write is table.value.update() over the shipped row updaters, and none of them names a group: insertRow() appends, and the 'group' stage re-clusters the result. The new row only lands under the header it was added from because it carries that group's key on every level — copied off a leaf already in the group, since a header's id stringifies its values and its groupKey holds only its own level.

So the button belongs to the deepest level only. An ancestor header — a Region banner with Category groups beneath it — pins one level and leaves the rest undecided, so there is no such thing as "the" row to add there; a button on it could only guess a category. Add from a {{ columnLabelById()[deepestLevel()] }} banner instead.
