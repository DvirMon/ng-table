## Throwing group order

The `groupOrder` comparator throws on every sibling pair it is handed. The table does not go down:
`sortClusters` catches, falls back to stable first-occurrence order for the affected levels, and
reports once per evaluation (D15). That fallback is a state `Default`'s DOM never reaches, which is
why it is pinned here rather than left behind a control.

<Canvas of={GroupingStaticStories.ThrowingGroupOrder} />

## Async grouping rule

One grouping level is decided by the server, over a real intercepted request. The point is the
*pending* window, which is otherwise invisible: while the rule is unresolved the whole rule set
abstains and the table holds the grouping that was last explicitly chosen, rather than flashing
ungrouped and back (D13). On resolution the level set becomes the rule's — a resolved rule overrides
the base choice rather than merging with it. `forceFailure` exercises the rule's required `onError`,
which must return an explicit boolean: `false` here, resolving the set to `[]`, which is "grouped by
nothing" rather than "no answer yet", and leaves every row on screen.
