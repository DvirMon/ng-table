# Gated Edit — Multiple Rows, Optimistic Save

Optimistic-only is a deliberate constraint here, not an arbitrary default: per
`docs/1-state/work/with-multiple-edit/1-design.md`, a save must close its row before firing so an
in-flight save is always `pending`, never `open` — otherwise a bulk-close op could silently
discard a live restore point. Pessimistic multi-row editing has no story for the same reason.

<Canvas of={GatedMultipleOptimisticStories.Default} />

## Forced failure

Rows still close immediately on Save All — closing never waits on the round trip. Each failed row
reverts to its pre-edit value and shows a Retry/Dismiss control.
