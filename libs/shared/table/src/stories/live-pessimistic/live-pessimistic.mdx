# Live / Pessimistic

Sibling of [`Live / Optimistic`](../live-optimistic/live-optimistic.mdx) — same
`liveOptimisticSchema` (`withOptimistic()` alone, no `withRowEdit()`, D39: the focus session *is*
the edit session), and the same three verbs (`captureEdit`/`patchEdit`/`releaseEdit`). The two
stories differ only in when the revert happens relative to the save request:

- **Optimistic** commits the typed value to `data` on blur, shows a non-blocking "saving…" badge,
  and only reverts *after* a failed save.
- **Pessimistic** (this story) reverts `data` back to the pre-edit value **immediately on blur**,
  before the request is even sent, and locks the field until the server confirms — so nothing
  ever looks committed early. On success, `patchEdit` reveals the confirmed value; on failure, the
  reverted value is already correct, so failure just lifts the lock. `revertEdit` is never called
  here — there's nothing left to roll back once the revert already happened before the request.
