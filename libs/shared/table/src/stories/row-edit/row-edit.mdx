# Row Editing

Nine stories along two axes: whether an edit session is **gated** (a button opens the row) or
**live** (focus delimits it), and whether a save is **optimistic** (the row closes before the
round trip settles) or **pessimistic** (it waits). Each combination is a fixed-mode host rather
than a toggle, because the mode is decided at construction.

Shared: `fixtures/schema.ts` and `fixtures/http.ts`, at the bottom of this page. Three hosts bring
their own stylesheet or schema, shown in their own tabs.

## Live Optimistic — updates and rollback

The edit session is focus-delimited: there is no button to open a row, so there is no edit session
to track, and no `withRowEdit()` is composed. `withOptimistic()` alone supplies the three rollback
verbs (`captureEdit` / `releaseEdit` / `revertEdit`): focus captures a restore point, blur commits
and saves, and a rejected save reverts to the captured value. `table.editing()` stays empty for the
whole story; `table.pending()` is exactly the in-flight set.

Also on this canvas: a screen-reader announcement on each pending-state transition, a "Simulate
leave page" guard demo (plus a real `beforeunload` listener), and an Undo control that reappears
for a few seconds after a delete settles, before its restore point is released.

<Canvas of={LiveOptimisticStories.LiveOptimistic} />

Under failure the edited value shows on screen immediately, same as the happy path. When the save
fails, the value reverts to what it was before the edit — the row was never in an "open for
editing" state, so nothing closes, it just reverts.

## Gated Multiple Optimistic

Optimistic-only is a deliberate constraint here, not an arbitrary default: a save must close its
row before firing so an in-flight save is always `pending`, never `open` — otherwise a bulk-close
op could silently discard a live restore point. Pessimistic multi-row editing has no story for the
same reason.

<Canvas of={GatedMultipleStories.GatedMultipleOptimistic} />

Under failure rows still close immediately on Save All — closing never waits on the round trip.
Each failed row reverts to its pre-edit value and shows a Retry/Dismiss control.

## Gated Bulk

Opening several new rows uses `createRow`'s array overload — one call, no consumer loop — and
saving them sends one `POST /api/rows/bulk` request instead of N separate ones, so a failure
reverts and reopens the whole batch together. `Gated Multiple Optimistic`'s Save All is the other,
older answer to the same open question: N independent requests, N independent outcomes.

<Canvas of={GatedBulkStories.GatedBulk} />

Under failure every row in the batch reverts to blank and reopens together — not some succeeding
while others fail, which is the contrast with Save All.
