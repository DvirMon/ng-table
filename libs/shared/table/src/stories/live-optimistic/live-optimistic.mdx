# Optimistic Updates & Rollback

Live + Optimistic: the edit session is focus-delimited (D39) — there is no button to open a row,
so there is no edit session to track, and no `withRowEdit()` is composed. `withOptimistic()`
alone supplies the three rollback verbs (`captureEdit`/`releaseEdit`/`revertEdit`): focus captures
a restore point, blur commits and saves, and a rejected save reverts to the captured value.
`table.editing()` stays empty for the whole story; `table.pending()` is exactly the in-flight set.

Also on this canvas: a screen-reader announcement on each pending-state transition, a "Simulate
leave page" guard demo (plus a real `beforeunload` listener), and an Undo control that reappears
for a few seconds after a delete settles, before its restore point is released.

## Forced failure

The edited value shows on screen immediately, same as the happy path. When the save fails, the
value reverts to what it was before the edit — the row was never in an "open for editing" state,
so nothing closes, it just reverts.
