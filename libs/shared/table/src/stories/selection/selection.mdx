# Selection

Three stories: `Multi` and `Single` are siblings, because the mode is a construction-time
argument rather than a toggle — `enableMultiRowSelection: false` is passed to `withSelection()`
at construction, so a single host switching between them would carry a dead branch. `Filtering ×
Selection` is where selection meets row churn from another feature.

Shared across `Multi`/`Single`: `fixtures/schema.ts` and `selection-story.css`, at the bottom of
this page. Both configs have the same shape — the mode is the `withSelection()` argument, not a
config field. `Filtering × Selection` uses the filtering domain's own invoice fixtures and
`filtering-story.css` instead — shown in its own tabs, not the shared section.

## Filtering × Selection

Two features composed, and the place their edges meet. A selected row that a filter moves out of
view stays selected — the opposite of MUI X's documented behaviour, which deselects it — and
clearing the filter brings the selection back unchanged. Column headers sort, so selection is
proven to survive both filtering and sort-driven row reordering, not filtering alone. The header
checkbox is the only select-all/clear gesture; each row has its own delete action.

One gap is rendered rather than papered over: nothing shipped reports how many selected rows are
currently hidden, so the canvas says so instead of computing a stand-in count in the story host.
The notice disappears on its own when that signal lands.
