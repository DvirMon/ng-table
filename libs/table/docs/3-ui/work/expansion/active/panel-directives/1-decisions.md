# Decisions — panel-directives (#199)

Grilled 2026-10-01. Source: [#199](https://github.com/DvirMon/ng-table/issues/199).
Upstream: E40, E41 in [`decisions/expansion.md`](../../../../../decisions/expansion.md).

## Dependency ranking

- **Core:** D1 toggle↔panel link (panel identity, `aria-controls`, path back to the toggle).
- **Dependent:** names/inputs, `inert` mid-leave, focus return → Esc owner, dev assertions.
- **Leaf:** stale-spec rewrite scope.

## Decisions

- 2026-10-01 — **D1** Toggle and panel link through a table-scoped registry provided by `ngpTable`, keyed by `RowId`: the panel registers on mount and unregisters on destroy, the registry mints the DOM ids, the toggle binds `aria-controls` only while its panel is mounted, and the panel gets its toggle element from the registry for focus return. Rejected: a derived deterministic id (`aria-controls` would point at a missing id while unmounted; focus return needs a second id plus `getElementById`) and consumer-passed ids (more markup, easy to mismatch).
- 2026-10-01 — **D2** Names: `ngpTablePanelToggle` (on the consumer's `<button>`) and `ngpTablePanel` (on the panel content element). Names what the person sees and avoids reading as tree expansion next to `ngpTableTreeToggle`. Rejected: `Expansion*` (mirrors `withExpansion()` but collides with the tree's "expand" wording) and `Detail*`. "Detail panel" goes into the glossary.
- 2026-10-01 — **D3** `ngpTablePanel` takes the `RowId`, not the `RenderRow`: `[ngpTablePanel]="row.id"`. The panel needs only the key (registry + `expansion().has(id)`), and the 1.6 side panel holds an id from `expansion()`, not a `RenderRow`. Rejected: `RenderRow` (symmetry with `[ngpTableRow]="row"` only).
- 2026-10-01 — **D4** `ngpTablePanel` binds `id` and `inert` through host bindings (`'[inert]': '!isOpen()'` covers a kept-mounted closed panel). The leave animation needs one write the binding can't make: in `DestroyRef.onDestroy`, after focus return, `renderer.setAttribute(host, 'inert', '')`, with a `//` comment on why. Verified in installed Angular 22.1.2 (`fesm2022/_debug_node-chunk.mjs`): `ɵɵconditional` destroys the `@if` view in the parent's update pass, before the view's own bindings refresh (`refreshView` returns early on a destroyed view), so `[inert]` never becomes `true` on a leaving panel. Destroy hooks run synchronously while the element is still connected; leave classes come after render and removal comes after the animation. angular.dev/guide/animations does not document this order, so a spec test pins it. Written with `Renderer2` (the user's call) — Angular's DOM-APIs guide says it behaves the same as the native API here. No `effect()` writes the DOM. Rejected: bindings only (leaves the panel focusable for the ~200ms leave, the gap E41 closes) and the consumer's `(animate.leave)` hook (hands the a11y back to the consumer).
- 2026-10-01 — **D5** Focus return targets only a live toggle (`registry.toggleOf(id)` still connected). When the row itself disappears with focus inside its panel (deleted, or filtered out — panel and toggle unmount together), the focus loss is the same as for any in-row control, so it belongs to core row/table keyboard navigation (ADR-0029 cat. 5, E43, [#201](https://github.com/DvirMon/ng-table/issues/201)); a note was added to #201. Rejected: the panel falling back to the table host (fixes the panel case only) and doing nothing.
- 2026-10-01 — **D6** Esc is handled by `ngpTablePanel`: a `(keydown.escape)` host listener calls `table.expansion.collapse([id])`, then focus return (D5) runs. It does nothing when `event.defaultPrevented` is set, so inner widgets that use Esc (select, combobox) and consumers can opt out without a new input. This goes beyond APG disclosure, which defines only Enter/Space (w3.org/WAI/ARIA/apg/patterns/disclosure); the product doc asks for "Esc closes". Rejected: an opt-out boolean input (`defaultPrevented` already covers it) and a consumer-owned recipe (every consumer re-writes it). Caveat (verified 2026-10-01, Angular 22.1.2 `_debug_node-chunk.mjs` :8162-8213): on one element, a directive's host listener and a template listener for the same event are merged into one native listener and run host-first, so a consumer `(keydown.escape)` on the `ngpTablePanel` element itself cannot opt out — only a handler on an element inside the panel (which receives the key first as it bubbles) can.
- 2026-10-01 — **D7** A kept-mounted closed panel stays `inert` (D4 unchanged). `hidden="until-found"` + `beforematch` (find-in-page opens a kept panel) is additive, only reaches kept-mounted panels (an unmounted panel can't be found either way), and does not replace `inert`: ng-primitives 0.130.3 sets `until-found` only once closed **and** at zero height, leaving its exit animation focusable, with no `inert` or focus handling (`fesm2022/ng-primitives-collapsible.mjs`). Left as [#209](https://github.com/DvirMon/ng-table/issues/209)'s open question; not a #199 blocker.
- 2026-10-01 — **D8** Focus return runs from the panel's own close paths and its teardown, never from an effect. `ngpTablePanel` gets a public `close()` (`exportAs: 'ngpTablePanel'`): `collapse([id])`, then return focus to a live toggle when `activeElement` is null, `<body>` (Safari doesn't focus a clicked button) or inside the panel. The Esc listener (D6) calls `close()`. The in-panel × is `(click)="panel.close()"`. `DestroyRef.onDestroy` returns focus only when focus is strictly inside the panel (so a toolbar collapse-all never pulls focus to a toggle), then writes `inert` (D4). Not covered: something other than the panel (toolbar, API) closing a kept-mounted panel while focus is inside — CDK Menu has the same limit. Grounded in [`discovery-focus-return.md`](discovery-focus-return.md): no reference library returns focus for an inline collapsible; those that return focus (CDK Dialog/Menu, ng-primitives overlay/dialog, React Aria, Radix) do it from their own close method or teardown, never an effect. `@angular/cdk` is not a dependency, so plain `.focus()`, not `FocusMonitor.focusVia`. Rejected: no `close()` (Safari mouse × and kept-mounted × lose focus) and an effect reacting to open→closed (no precedent for moving focus that way).
- 2026-10-01 — **D9** Dev-mode checks. Throw: `ngpTablePanelToggle` or `ngpTablePanel` on a table without `withExpansion()` (same as `assertTreeComposed` in `ngp-table-tree-toggle.directive.ts`); a second `ngpTablePanel` mounted for a `RowId` that already has one (message names the id; one panel per row). Warn: a toggle with no accessible name (`afterNextRender`, as the tree toggle does). Nothing added for a toggle outside `ngpTableRow` (Angular's own DI error) or a toggle whose panel isn't mounted (that is just "closed"). The `withExpansion()` check adds no coupling: the directives already depend on the state layer, which stands alone without them. Rejected: a duplicate panel only warning, and several panels per row (`aria-controls` listing every id).
- 2026-10-01 — **D10** `ngpTablePanelToggle` handles the click: a host `(click)` calls `table.expansion.toggle(id)`, and the directive emits nothing (matches `ngpTableTreeToggle` and #209's direction). Single-open is not the directive's job: it moves into the state layer as `withExpansion({ multi?: boolean | (() => boolean) })`, default `true`, using `withRowEdit`'s `multiple` rule (in single mode every write keeps only the last opened row; switching live to `false` closes all). Every writer then follows it (toggle, Esc, API, #201 stepping). This reverses OQ-exp-1 ("a recipe, not a mode"): that ruling assumed the consumer writes the click, but here the directive's host listener always runs first (verified, Angular 22.1.2 `_debug_node-chunk.mjs` :8162-8213), so the recipe became a second write. The state change is its own issue, [#210](https://github.com/DvirMon/ng-table/issues/210); #199 doesn't wait on it. Rejected: an a11y-only toggle where the consumer writes the click; a `closeOthers` consumer recipe (two writes per switch); single/multi logic in the directive (covers clicks only).
- 2026-10-01 — **D11** Accessible names are fully consumer-owned. `ngpTablePanelToggle` has no label input, no default text and no nameless warning; the consumer writes `aria-label` or text on the native `<button>`. The library owns relations only (`aria-expanded`, `aria-controls`, the panel `id`). Supersedes D9's nameless warning (D9's two throws stand) and amends ADR-0029 #3 (label input + "Toggle details" default). Grounded in ng-primitives 0.130.3: `NgpCollapsibleTrigger` binds only `aria-controls`/`aria-expanded`, `NgpAccordionContent` uses `aria-labelledby` to its trigger, pagination icon buttons ship no label (`fesm2022/ng-primitives-{collapsible,accordion,pagination}.mjs`). The tree toggle's shipped TR39 warning becomes the odd one out; removing it is [#209](https://github.com/DvirMon/ng-table/issues/209)'s. Rejected: a `ngpTablePanelToggleLabel` input with a default (ADR-0029 #3 as written) and keeping the warning.
- 2026-10-01 — **D12** Spec rewrite scope for `3-ui/directives/expansion.md`, done at `/to-spec`. Rewrite in place, keep the filename, `version: 1.0`, `code: none`. **Delete:** the three tiers, `ngpTableExpandable`, the `<tr>` host and nesting guard, `ngpTableExpandContent` and its slide CSS, "Default presentation". **Replace:** "Lazy and persistent" (E7) with E40 (unmount default, keep-mounted recipe, `release()`), and the dev-mode assertions with D9 + D11. **Add:** toggle, panel, registry/ids (D1–D3, D13), `inert` (D4, D7), focus return and Esc (D5, D6, D8), click and `multi` (D10, #210), names (D11), the a11y contract by ADR-0029 category, and recipes (slide, keep-mounted). **Keep, reworded:** the rejected container directive and `hostDirectives`. **Rewrite:** "reuse ng-primitives" as "copy patterns, no dependency" (#209). **Close To-Drill:** accordion mode (#210), `expandAll` directive (stays a recipe, OQ-exp-4).
- 2026-10-01 — **D13** The registry builds a panel's DOM id from a per-table prefix plus the escaped `RowId` (e.g. `ngp-t1-panel-r42`), not a mount counter. The same row gets the same id on every mount and on both server and client, so hydration can't mismatch `aria-controls`, even though the library has no stated server-rendering position. `RowId` is `string | number`, so it is escaped before use. Rejected: a mount counter (the id changes on every remount and can differ between server and client).
- 2026-10-01 — **Failure modes covered:** withExpansion missing (D9), duplicate panel (D9), row removed or filtered with focus inside (D5 → #201), focus inside a leaving panel (D4, D8), Esc inside a nested widget (D6), Safari not focusing a clicked button (D8), external close of a kept-mounted panel (D8, known gap), single-open (D10 → #210), a panel scrolled away under virtual scroll (E42, registry unmount), ids across remount and hydration (D13).
- 2026-10-01 — **isComplex: true.** It needs new internal types (a table-scoped registry token provided by `ngpTable`), an ordering-sensitive teardown (`onDestroy` focus-then-`inert`, pinned by a spec test against Angular 22.1.2), and grounding against existing directive source before building.
- 2026-10-01 — **D14** Build order: #199's implementation waits for [#209](https://github.com/DvirMon/ng-table/issues/209)'s shared collapsible core (the toggle's click, `aria-expanded`, `data-expanded`, the missing-feature throw); the spec does not. The registry, `inert`, focus return, Esc and `close()` are panel-only and not part of the core. Rejected: building #199 first and having #209 extract the trigger logic from two shipped directives afterwards, and blocking the #199 spec as well.
