# collapsible-core — decisions (#209)

- **2026-10-01** — `capabilityLogPath: null`: the core spans two capabilities (tree, `libs/table/docs/decisions/tree.md`; expansion/panel, `libs/table/docs/decisions/expansion.md`). Rows that bind one capability go to that capability's log.

## Dependency ranking

- **Core:** N1 — the core's contract with each feature (what it binds; how it reaches `table.tree` vs `table.expansion` without either reading the other).
- **Dependent:** N2 whole-row click (on N1); N3 sequencing with #199 (on N1).
- **Leaf:** N4 tree toggle retrofit to ADR-0029's default label.

## Decisions

- **2026-10-01** — **D0** *(library-text part corrected by D8)* Settled upstream, not re-grilled: library text follows ADR-0029 cat. 3 (generic default label, no dev warning), superseding TR39/TR46 for the tree toggle; panel hiding is `inert` per #199 D4 — `until-found` is at most a later add-on for kept-mounted panels. Prior logs (`tree.md` TR33–TR46, `expansion.md`) hold no ruling against an internal core; tree-ui-layer D1 rejected only a shared *public* toggle.
- **2026-10-01** — **D1** The core holds only logic identical in both features; anything that branches per feature stays in the feature directive, even when that duplicates it (e.g. disabled handling is written twice). The core's contract carries no field one feature doesn't need. Rejected: a core owning disabled with a per-feature `isEmpty` flag (a field the panel never uses).
- **2026-10-01** — **D2** The core binds `aria-expanded` and `data-expanded` from a plain `isOpen(): boolean`, and `(click)` to `toggle()`; its contract is those two members. TR45's "omit `aria-expanded` on a disabled toggle" is dropped: a tree leaf now shows `aria-expanded="false"`, unreachable behind TR38's `disabled` + `aria-hidden` (TR46's reasoning). The tree keeps its own disabled branch (`disabled`, `aria-hidden`, `data-disabled`) per D1. Rejected: a tri-state `expanded(): boolean | null` (re-imports the tree's disabled branch into the core) and per-feature `aria-expanded` bindings (duplication with nothing to branch on). Tree log: TR47 (D0), TR48 (this).
- **2026-10-01** — **D3** *(superseded by D8)* The ADR-0029 cat. 3 label rule (consumer label input, generic default, `aria-label` only when the button has no name) is its own shared helper in the directives layer (`libs/table/src/directives/`), usable by any directive — both toggles, sort headers, selection. It is not part of the collapsible core, which stays `isOpen` + `toggle` (D2). Rejected: the label inside the collapsible core (the rule spans every directive, not only collapsibles).
- **2026-10-01** — **D4** The core reaches no store: each feature directive supplies its own `isOpen` and `toggle` (D2), so the core imports neither `table.tree` nor `table.expansion` and E37 holds by construction. The wiring mechanism (`hostDirectives`, base class, or function) is for the architecture doc.
- **2026-10-01** — **D5** Whole-row click is out of #209: TR36/TR44 stand (consumer `(click)` on the `<tr>`, the recipe #189 s4 shipped). Revisit when selection adds its own row click, with #201's row interactions. #209 does not touch the row directive. Rejected: an opt-in row input now (reverses TR36/TR44 and must settle selection precedence before selection exists).
- **2026-10-01** — **D6** Sequencing: #199's planning PR merges first (ADR-0029 must be on `main` before #209's planning docs link to it); then #209 ships the core, the removal of the tree toggle's nameless warning (D8) and the tree-toggle retrofit; #199's panel-toggle slice is blocked by #209 and builds on the core. #199's panel-content slice (registry, `inert`, Esc) is independent. Rejected: #199 first and extract after (two toggles written, then reworked) and folding the core into #199 (puts the label helper and tree changes inside a panel issue).
- **2026-10-01** — **D7** The core always binds `type="button"` on its host, overriding any consumer `type`: a toggle that submits a form is never correct, so there is nothing to opt out of (ADR-0029 cat. 1). Stories can drop their manual `type="button"`. Rejected: setting it only when absent (keeps a `type="submit"` with no known use, and needs a construction-time check) and leaving it to the consumer (a forgotten `type` inside a `<form>` submits on every toggle click).
- **2026-10-01** — **D8** Corrects D0's library-text part and reverses D3. ADR-0029 cat. 3 was amended the same day (#199 E55): accessible names are consumer-owned — the library writes no text (no label input, no generic default, no dev warning); the consumer names the control on the native element (`aria-label` or visible text). So there is no label helper, and the consumer is the only writer of `aria-label` (no collision with the library). #209's share is removing the tree toggle's shipped nameless warning (TR39, TR46), per ADR-0029's Consequences. Tree log: TR47 (rewritten).
- **2026-10-01** — **D9** Failure-mode pass (trigger on a native `<button>`): the "feature not composed" dev throw (TR40) stays per feature — message and guard differ, so D1 keeps it out of the core; a disabled native button fires no click, so the core needs no guard; keyboard activation stays native (ADR-0029 cat. 4); each feature keeps its `button[…]` selector. Nothing else open.

## Complexity

- **2026-10-01** — `isComplex: true`. The core's wiring mechanism (`hostDirectives`, base class, or function — D4) is unresolved, and the core is a shared internal piece across two features; it needs grounding against Angular before anyone builds it.
