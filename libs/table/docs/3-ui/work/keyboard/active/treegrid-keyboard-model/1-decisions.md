Workspace: `libs/table/docs/3-ui/work/keyboard/active/treegrid-keyboard-model/`.
No capability decisions log exists for `keyboard`; `capabilityLogPath` is `null`
because the model is table-wide (tree, expansion, grouping, selection, row editing).

Settled upstream, not re-decided here: ADR-0029 cat. 5 (directives own keyboard
navigation, APG grid/treegrid, single Tab stop; a11y never opt-in), E43 (row
stepping owned by core row/table directives; panel and tree plug in), tree-ui-layer
D2/D4 (today: `role="table"`, `aria-expanded` on the toggle button).

## Decisions

- **K0** (2026-10-10, scope) — #196 (treegrid) and #201 (grid keyboard navigation) are one capability, grilled together in this workspace. `/to-issues` slices it later (core navigation before the tree plug-in). Discovery for K12 (where focus position lives): `discovery-focus-ownership.md` (2026-10-13).
- **K2** (2026-10-10, K2) — Focus unit follows APG: `grid` tables use cell focus only (APG grid has no row focus); `treegrid` tables focus rows and cells (APG treegrid example). On a row: ↑/↓ move row to row, → expands a collapsed row, → on an expanded or leaf row enters its first cell. On a cell: arrows move cell to cell, ↑/↓ stay in the column, ← on the first cell returns to the row. Row-only focus rejected — neither APG pattern allows it (ADR-0029 sets APG as the bar). Cell-only treegrid rejected — it drops →/← expand/collapse, which #196 asks for.
- **K1** (2026-10-10, K1) — Host role is fixed at construction from the composed features, never from live data: `withTree()` composed → `treegrid`; otherwise `grid`, including static read-only tables (ADR-0029 cat. 5 as written; browse-mode loss on static tables accepted). A runtime role switch (treegrid only while a row is expandable) rejected — APG needs no such switch (a treegrid with only leaf rows is valid), and flipping the role mid-session resets screen-reader context and roving focus. Keeping `role="table"` for static tables rejected — would amend ADR-0029 and needs an "interactive" rule. Supersedes tree-ui-layer D2's role half; ADR to be written via /domain-modeling once K5 (toggle fate) settles.
- **K3** (2026-10-10, K3) — Single Tab stop via roving tabindex (one element `tabindex="0"`, the rest `-1`). Re-entering with Tab returns to the last focused cell/row. First entry lands on the first data row: its first cell in `grid`, the row itself in `treegrid`; header cells are reached with ↑. Landing on the first header cell rejected (a non-sortable header is a dead stop; treegrid header row has no row focus). No memory rejected (Tab out to a toolbar and back loses the place). A remembered target that disappears is K9's job.
- **K13** (2026-10-10, K13) — Keyboard navigation must work under `withVirtualScroll()` (drafted, not built), where rows outside the window are not in the DOM. So: the focused position is stored as data (row id + column id), never a DOM element reference; arrow keys compute the next target from `renderRows()` order, not DOM siblings; moving to an unrendered row scrolls it into the window (`scrollToIndex`) and focuses it after render; `aria-rowindex`/`aria-rowcount` carry the true position and total (ADR-0005 fields). Constrains K3, K4, K9.
- **K4** (2026-10-10, K4) — Key map is APG's as written: arrows, Home/End, Ctrl+Home/Ctrl+End with their row-vs-cell meanings (APG grid + treegrid). Page Up/Page Down ship: step = visible row count — `withVirtualScroll()`'s `visibleRange` when composed (pure data), else measured from the scroll container at keypress (fallback 10); same column; an off-window target goes through scroll-then-focus (K13). No wrap anywhere: at the first/last row or edge cell focus does not move (APG data grid: "focus does not move"; E43). Wrap rejected — silent jump disorients screen-reader users who rely on the edge as a position signal, a held key would cycle forever, and under virtual scroll it is a full re-render jump; APG allows wrap only in layout grids. Fixed step rejected (feels wrong on tall/short viewports); not shipping rejected (focused row scrolls out of the window).
- **K5** (2026-10-10, K5) — In `treegrid`, the row owns `aria-expanded` and `aria-level`; `button[ngpTableTreeToggle]` keeps its selector and markup but becomes a pointer-only target: `tabindex="-1"` (skipped by Tab-in-row), no `aria-expanded` (single owner, tree-ui-layer D5), `aria-hidden="true"` (no duplicate control announced). A click still toggles and moves the roving focus to that row. Keeping it a full control rejected (two controls announce one state; breaks D5). A non-button element rejected (reverses D4's button-only selector; template change per mode). Together with K1 this supersedes tree-ui-layer D2; the ADR is written once K12 settles, covering the whole table-wide model in one pass.
- **K5b** (2026-10-10, K5) — Enter on a focused `treegrid` row toggles it when expandable (mirrors →/←, #196's ask) and does nothing on a leaf row. A consumer row action (open details, edit) stays on its own control inside the row, reached with Tab (K6). A leaf-row "row activate" output rejected (new public output; Enter would mean two things by row). Enter doing nothing on rows rejected (drops #196's ask).
- **K6a** (2026-10-10, K6) — Consumer widgets in cells follow APG's two modes, auto-detected per cell. One non-text widget (checkbox, button): navigation focuses the widget itself; Space/Enter stay native. A text input, select, or several widgets: navigation focuses the cell; Enter/F2 moves into its widgets (arrows/Tab then belong to them), Esc returns to navigation. The library sets `tabindex="-1"` on cell descendants so the grid stays one Tab stop. Keys from editable targets (input, textarea, select, contenteditable) are never handled as navigation. In `treegrid` row focus, Tab walks the focused row's widgets, then leaves the grid (APG). "Always cell focus, Enter/F2 to enter" rejected (extra keypress per checkbox row). Leaving widgets in the Tab order rejected (one Tab stop per widget per row; breaks K3).
- **K6b** (2026-10-10, K6) — Consumer key handlers win through the standard DOM contract: the grid listens on its host in the bubble phase and skips any key event whose `defaultPrevented` is true. Example: `(keydown.escape)="cancelEdit(); $event.preventDefault()"` keeps focus in the input; without `preventDefault()` the grid also exits widget mode. One general override for every key, no config (ADR-0029 (c), explicit opt-in). Grid-always-acts rejected (consumer cannot keep focus in an input after Esc). `stopPropagation()` as the override rejected (hides the key from every other ancestor listener — dialogs, global shortcuts).
- **K7** (2026-10-10, K7) — The header row is part of arrow-key navigation, every header cell included. ↑ from the first data row reaches it; ←/→ move across it. A sortable header focuses its `ngpTableSort` button (single-widget cell, K6a) and Enter/Space sorts; a plain header cell takes focus itself. In `treegrid` the header row has no row focus: ↑ from a focused first data row goes to the header's first cell. Focusing only functional headers rejected (no ↑ target under a plain header; breaks column alignment). Header outside navigation rejected (a Tab stop per sortable column; breaks K3).
- **K8a** (2026-10-10, K8) — Arrow keys stop on group header rows (ADR-0029 cat. 5): in `grid` as one full-width cell, in `treegrid` as a row with →/← collapse/expand. ↓ from a group header back into data restores the remembered column. E43 stays true for what it ruled on: a single-open detail panel follows the next _data_ row, skipping group headers — the two sources are scoped, not in conflict. Skipping headers in navigation rejected (a collapsed group's header is its only row; skipping makes it keyboard-unreachable). A per-table grouping flag rejected (new public option for a behavior APG already answers).
- **K8b** (2026-10-10, K8) — An open detail panel is an arrow stop: one full-width cell placed in navigation order right after its row. ↓ from the row lands on it; Enter/F2 goes inside (multi-widget cell, K6a); Esc inside closes it and returns focus to the toggle (E49/E51 unchanged — the panel's `preventDefault()` makes the grid skip the key, K6b). Closed panels are unmounted, so arrows never see them. The toggle keeps the APG disclosure contract unchanged; APG disclosure says nothing about reaching the content, and inside a grid "next in reading order" is the next row. Replaces `3-ui/directives/expansion.md`'s "the next Tab lands inside the panel". Tab-from-toggle entry rejected (arrowing screen-reader users never meet the panel; Tab gains a special meaning on toggle cells only). Both entries rejected (two entry rules for one panel).
- **K9a** (2026-10-13, K9) — When the focused row is deleted or filtered out, focus moves to the row now at its old position in navigation order (clamped to the last row), same column. Empty table → first header cell; no header → the table host. Recovery therefore needs the previous row order (discovery: every recovering library keeps it). Precedent: React Stately, MUI X. Previous-row rejected (no previous after deleting the first row; needs a fallback anyway). Reset-to-first rejected (deleting row 400 of 500 throws the user to the top).
- **K9b** (2026-10-13, K9) — When the focused row is hidden because an ancestor collapsed (collapse-all, a parent's toggle click, API), focus moves to the nearest visible ancestor row — row focus in `treegrid`. The user lands on what hid their row and can → to reopen it (APG ←-collapse direction; file-tree behaviour). Treating hidden like removed (old index) rejected — after collapse-all that row is usually an unrelated top-level sibling.
- **K9c** (2026-10-13, K9) — When the focused row moves (sort, reorder, live update), focus follows the same row id + column to its new position; under virtual scroll that is scroll-then-focus (K13). Staying at the position rejected — the focused item silently changes to a different row with no announcement (discovery: AG Grid's index-keyed focus drifts this way).
- **K9d** (2026-10-13, K9) — Recovery (K9a–c) moves DOM focus only when focus is inside the grid. When focus is anywhere else, only the stored position and the `tabindex="0"` target are re-pointed — no `.focus()`, no scroll; the next Tab into the table lands on the recovered position. Always calling `.focus()` rejected — typing in an outside search box that filters the table would pull the caret into the grid on every keystroke.
- **K12** (2026-10-13, K12) — The table store holds the focused position only: an always-present core member `{ rowId, columnId } | null` plus a public write (e.g. focus a newly added row); names decided in the spec. The engine keeps it valid when rows change (ADR-0006 removal hook; K9a needs the previous order). `withVirtualScroll()` reads it to keep the focused row mounted; a side panel anywhere reads it. Keys, tabindex, roles and `.focus()` stay entirely in the directives (ADR-0029). Evidence: `discovery-focus-ownership.md` — virtualization survival follows from id-keyed non-DOM addressing (K13); TanStack v9, MUI X and AG Grid expose a read + write; React Aria keeps focus in its state layer too. Cost accepted: one member on every table, including tables rendered without the directives (opt-in, TanStack's way, is barred by ADR-0029). Public read-only variant rejected (consumers cannot focus a row they just added). Directive-only via `exportAs` rejected (needs a new directive→feature channel for `withVirtualScroll`, re-derives removal recovery in the view, and a side panel outside the template has no path).
- **K11** (2026-10-13, K11) — A side panel anywhere follows focus by reading the store's focused position (K12) — no DOM or directive path needed. "The panel follows the focused row in single-open" (ADR-0029 cat. 5, E43) applies only while a single-open panel is already open: focus moving to another data row (group headers skipped, K8a) switches the open panel to that row; with no panel open, arrowing opens nothing. Same rule for inline and side panels — the user opts in by opening one. A per-table `followFocus` flag rejected (new public option every side-panel consumer must remember). Always following in single-open rejected (every ↓ reflows rows for inline panels).
- **K13b** (2026-10-13, K13) — When the focused row is scrolled out of the virtual window (mouse wheel, scrollbar), `withVirtualScroll()` keeps it rendered in addition to the window (reads K12's position; React Aria `persistedKeys`, MUI `focusedVirtualCell`). DOM focus never drops to `<body>` (ADR-0029 cat. 6); the next arrow key continues from it and scrolls back. Parking focus on the grid host rejected — screen readers announce the whole grid on the park, and an unforeseen unmount still drops focus to `<body>`.
- **K10** (2026-10-13, K10) — Div-grid host (ADR-0005) has full parity: same keys, same focus model; roles `grid`/`treegrid`, `row`, `gridcell`, `columnheader` applied unconditionally; `aria-rowindex`/`aria-colindex` always bound because a div host has no native order for assistive tech.
- **K9e** (2026-10-13, K9) — Focused column hidden (column visibility) → focus moves to the column now at the old position, clamped (mirrors K9a). Focused column reordered → focus follows the column id (mirrors K9c).
- **K3b** (2026-10-13, K3) — A pointer click on a cell or row (not on a widget) moves the stored position there; cells are `tabindex="-1"` so the browser focuses them natively. `:focus-visible` keeps mouse clicks ringless; ring styling is the consumer's (ADR-0026).
- **K6c** (2026-10-13, K6) — Filter inputs in a header cell are text widgets under K6a (Enter/F2 in, Esc out) — no special case. Nested grids (e.g. a grid inside a detail panel) need no rule: the inner grid calls `preventDefault()` on every key it handles (it must anyway, to stop page scroll), so the outer grid skips it (K6b).
- **K4b** (2026-10-13, K4) — RTL: under `dir="rtl"`, ←/→ swap meaning, including treegrid expand (←) and collapse (→).
- **K14** (2026-10-13, scope) — This capability ships navigation only. Selection keys (Space toggles the focused row, Shift+↑/↓ extends, Ctrl+A selects all) are `withSelection`'s job, plugged in by its own directive through the same plug-in shape as tree →/← (K5) and panel-follow (K11); navigation exposes the hook. Shipping selection keys here rejected (drags range/anchor semantics into this epic). No selection keys rejected (keyboard range selection would never exist).
- **K5c** (2026-10-13, K5) — Attribute ownership under `treegrid` (extends tree-ui-layer D5, one owner per attribute): `ngpTableTreeRow` binds the row's `aria-level` and `aria-expanded` (tree state is its own); core `ngpTableRow` keeps `role`, `aria-rowindex`, `data-*`; `ngpTableTreeToggle` binds none of them (K5).
- **K12b** (2026-10-13, K12, spec) — The focused position is an area-discriminated union: `{ area: 'header'; columnId } | { area: 'body'; rowId; columnId | null } | { area: 'panel'; rowId }`, or `null` when nothing was focused yet. Body `columnId: null` = row focus (treegrid) or a group header's full-width cell (grid). Member: `table.focus()` read, `table.focus.moveTo(target)` write (callable + method, like `table.expansion`). K12's plain `{ rowId, columnId }` rejected — header cells (K7) and open panels (K8b) need sentinel nulls, a silent-misread risk.
- **K12c** (2026-10-13, K12/K9d, spec) — `moveTo()` follows K9d: repoints the stored position and the `tabindex="0"` target; DOM focus moves only if focus is already inside the grid, or with `{ focusElement: true }` ("add row, then focus it" from a toolbar). Always-focus rejected — a write from an effect would steal focus. Never-from-outside rejected — the store holds no element, so a consumer has no path to focus a new row.
- **K14b** (2026-10-13, K14/K6b, spec — derived) — The feature-key plug-in is K6b's DOM contract, no registration API: a feature directive (tree row, panel, future selection) handles its key on its own element in the bubble phase and calls `preventDefault()`; core navigation skips prevented events. Treegrid "← to parent" stays in core, computed from render order (nearest earlier row with smaller depth).
- **Complexity** (2026-10-13) — `isComplex: true`: new core store member (K12), a key plug-in mechanism shared by tree, expansion and selection (K5, K11, K14), a virtual-scroll contract (K13b), and an ADR superseding tree D2 — needs an architecture doc grounded against `src/directives/` and `engine/` before slicing.
- **K15** (2026-10-27, tasks) — `focusElement` reaches `ngpTable` through a public counter, `table.focus.focusRequests: Signal<number>`, +1 per accepted `moveTo(…, { focusElement: true })`, never reset; the directive's sync effect (#235) focuses the current target after render. Counter over a one-shot flag: "add row, then focus it" writes before the row's element exists, so the request must outlive the write. Public over an internal WeakMap (would be the first `directives/` → `engine/` import; "no private store members") and over a last-write record (a recovery write would overwrite a pending request). Proof: [discovery-focus-element-channel.md](discovery-focus-element-channel.md) (Ariakit `moves`). Resolves architecture open question 1.
- **K16** (2026-10-27, tasks) — K12b (area union) and K12c (`focusElement` opt-in) re-challenged and kept; the directive writes all three areas, and default DOM focus would steal it from side-panel "next" buttons, deep links and effect-driven writes. A `moveTo(rowId)` shortcut rejected for now (consumer case is one line). Name stays `TableFocus`, not `FocusSlice`.
- **K17** (2026-10-27, tasks) — The unrendered-target check returns the offending id (`findUnrenderedId`) rather than an `is*` boolean, so the report names it in one pass; every rejected write reports (no lifetime dedupe), not gated by `ngDevMode`.
- **K18** (2026-10-27, tasks) — #232 is tested at the store seam (S1) only — no DOM exists in this slice; DOM focus and a11y behavior are tested at the directive host (S2) in later slices. Step 2's plan trimmed from 9 to 5 tests.
- **K19** (2026-10-27, tasks) — withExpansion's follow-focus effect tracks only `focus()`; `multi()` and the open set are read untracked. Tracking the open set rejected — a programmatic `toggle(B)` while focus rests on A would snap the panel back to A; tracking `multi()` rejected — a mode flip would move the panel with no focus move.
- **K20** (2026-10-27, tasks) — "Data row" for the follow rule is `indexById().has(rowId)` on a `body` target; group-header ids are synthetic and absent, `header`/`panel` targets never switch. A `renderRows()` scan for `kind` rejected (O(n) per focus move for the same answer).
- **K21** (2026-10-27, tasks) — #235 slice scope: `role="grid"` on every table until #239 adds `treegrid` (a temporary `grid` on a tree table is valid ARIA); group header rows stay out of the arrow order and get no tabindex until #240; `keyboard-nav.ts` lives in `directives/` (only the view calls it; resolves architecture open question 5); the editable-target key skip is deferred to #237.
- **K22** (2026-10-27, tasks) — Key map: `metaKey` counts as Ctrl for Ctrl+Home/End (Cmd on macOS); Ctrl/Cmd+Arrow returns `null` and is left to the browser (APG defines none in a grid); parameter shapes are named `NavOrder`, `BodyCell`, `NavKey` in `keyboard-nav.types.ts`.
- **K23** (2026-10-27, tasks) — `ngpTable.activeTarget` = `focus()` as is when non-null (no fallback for header/panel targets — those slices define them); first-entry default is `null` when there is no non-group row or no render column; typed plain `Signal<FocusTarget | null>` (cells reach it through `NGP_TABLE_STORE` typed `<unknown>`).
- **K24** (2026-10-27, tasks) — `ngpTable`'s sync effect skips `.focus()` when `document.activeElement` is already inside the target cell (a clicked in-cell button keeps focus), and gates K9d on a remembered focus-within flag (set on `focusin`, cleared on `focusout` whose `relatedTarget` leaves the host) instead of a live `activeElement` check — removing the focused cell drops focus to `<body>` with no `focusout`. #235 step 3 owns it.
- **K25** (2026-10-27, tasks) — #233 splits into three code steps run in order (rows+columns, collapse, closed panel) plus an independent docs step; S2→S3 is a shared-file edge (both edit `recoverFocus` and the effect), kept linear to avoid conflicts. One code step rejected (test plan too large to review).
- **K26** (2026-10-27, tasks) — `recoverFocus` takes the previous and next `RenderRow[]` plus the `rows()` id set, so the collapse walk reads depth/`isExpanded` with no second signature; tested only through `createTable` (seam S1), no separate `focus.spec.ts` — the issue's AC overrides the architecture table's `(+ .spec.ts)`.
- **K27** (2026-10-27, tasks) — Recovery edge results: a row in `rows()` but not rendered uses the old-index rule until a rule claims it; a panel target whose row is deleted keeps `area: 'panel'` on the new row and the closed-panel rule converts it; no rendered column left with rows remaining → `null` (a `columnId: null` body target would mean a group-header cell in grid); row focus (`columnId: null`) stays `null` through the column rule.
- **K28** (2026-10-27, tasks) — A group header gone from render counts as hidden (→ ancestor walk) when its nearest earlier still-rendered ancestor now has `isExpanded === false`; otherwise it was regrouped away → old-index rule. A hidden row with no rendered ancestor also falls back to the old-index rule.
- **K29** (2026-10-27, tasks) — Recovery's panel→body write must not trigger single-open follow-focus (it would reopen the closed row and undo a consumer's `toggle`). Fixed in `withExpansion`'s `followFocus`, which ignores a body target on the same row as the previous panel target. An engine-side "recovery write" flag rejected — it would make the engine aware of K11.
