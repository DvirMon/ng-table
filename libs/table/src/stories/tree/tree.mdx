# Tree

Hierarchical row expansion by parent-child links, navigated via outline expand/collapse. One story, one lesson, one canvas — in the order worth reading them.

**`Basic` is the one to copy.** Its host composes `withTree({ parentId: row => row.parentId, initial: [...] })` and nothing else, so nothing in its source is another lesson's setup — no second feature and no row handler.

Each story composes the fewest features its lesson needs. Where a second feature does appear — `withFiltering()` in `Filtered` — the page says what it is there to make visible.

For group-header expansion, see [`Table / Grouping`](?path=/docs/table-grouping--docs), its Collapsible section. For a tree chevron beside a panel chevron within groups, see [#190](https://github.com/DvirMon/ng-table/issues/190)'s `expansion/panel-in-groups/` story. The [tree UI spec](https://github.com/DvirMon/ng-table/blob/main/libs/table/docs/3-ui/directives/tree.md) describes the directive pair and styling recipe.

Shared across all of them: `fixtures/schema.ts` (one column list and one `treeConfig`) and `tree-story.css`. Those are at the bottom of this page, once.

## Basic — the whole feature, with nothing else on

`withTree({ parentId: row => row.parentId, initial: [...] })` and nothing else: no predicate, no second feature. One flat data set linked by `parentId`, displaying an outline view to depth 3. Click the chevron to open or close a parent; reopen a closed parent and its previously-open descendants are restored (deep restore, TR36). Expand all / Collapse all operate on every expandable row, and the readout displays the three-state tree state (All open / Some open / None open). 

The toggle appears on every row in the name cell and reads 'Children of [name]' (TR39); leaf toggles render disabled and invisible but keep their width for label alignment (TR38). Tab navigation reaches only parents; leaf toggles are skipped (TR36). Applies the shared tree styling recipe, which includes reduced-motion support.

## Filtered — matches with their ancestors shown

`withFiltering({ schema: treeFilters })` + `withTree({ parentId: row => row.parentId })`. As you type "review", ancestors of each match are kept and shown open automatically (default reveal). Context rows are dimmed by the recipe. The row count stays fixed on the number of matches, not visible nodes. A parent whose name matches but none of its children do renders a hidden, disabled toggle (TR38, 2.6). Close a revealed parent and it stays closed while you keep typing; clear the filter and the branches you opened before filtering are open again (2.4).

## Whole-row click — when the page owns the row handler

`withTree({ parentId: row => row.parentId })` only, no toolbar. Clicking anywhere on a parent row's text toggles its expansion, while the toggle button (chevron) still works independently. The toggle's click bubbles to the row handler, which must guard against it — this story shows why the page (not the table) is responsible for that guard. A leaf row does not respond to clicks.

The handler is the tree UI spec's guard written out with named booleans: skip when the target is inside `[ngpTableTreeToggle]` (an `instanceof Element` guard, no type assertion), skip a row without children, else toggle. The CSS adds `cursor: pointer` to rows that can be toggled.
